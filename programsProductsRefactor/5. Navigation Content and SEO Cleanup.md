# 5. Navigation Content and SEO Cleanup

Status: Not Started  
Depends On: Tasks 2-4

## Goal

Remove stale Shop/Book/cart/cohort language and make every Programs, Products, and registration entry point match the implemented home-page sections.

## Context

- `navLinks` currently contains Programs, The Book, Shop, Coaching, and Journal hash links.
- `SiteHeader` has a fake cart count of `3`, a visual-only search button, `Book a call`, and mobile `Shop the store`.
- `Topbar` advertises free shipping, signed book copies, and fall coaching slots.
- Hero/About CTAs target Programs, Book, or Coaching.
- Footer groups repeat all three mock program names and mock shop categories; Contact, legal, and social links remain separate placeholders.
- `app/layout.tsx` metadata mentions `training programs` and `shop drops`.
- `components/section/shared/mobile-nav.tsx` duplicates old Shop/Book-a-call language but is not imported by the production header.

## Files / Areas Likely Involved

- `lib/content/home.ts`
- `components/section/shared/site-header.tsx`
- `components/ui/resizable-navbar.tsx` only if its action slots need simplification
- `components/section/shared/site-footer.tsx`
- `components/section/shared/topbar.tsx`
- `components/section/shared/mobile-nav.tsx`
- `components/sections/home/hero-section.tsx`
- `components/sections/home/about-section.tsx`
- `app/layout.tsx`
- Header/footer/navigation/metadata assertions in `test/home.spec.ts`

## Required Changes

- Replace Book/Shop navigation with one `Products` item targeting the new `#products` section.
- Keep `Programs` targeting the real program section and make the primary coaching action `Register`, targeting the registration section.
- Remove the cart icon/count and every `Shop the store`/`Book a call` action. Do not imply scheduling or onsite ecommerce.
- Leave the visual-only Search control alone unless it creates a layout problem; search is outside this refactor. Continue marking it as a placeholder if retained.
- Replace or remove topbar messages that claim shipping, signed-copy availability, fake cohort timing, or other unapproved facts. Do not invent promotional replacements just to keep the marquee populated.
- Update Hero and About program/product CTAs and supporting copy so all hashes resolve exactly once and no stale Book/Shop/Coaching action remains.
- Rebuild footer Programs/Products link groups from approved centralized content where practical. Products without individual sections may link to `#products`; registration links target the form.
- Remove mock program names, mock shop categories, ecommerce Returns wording, and stale shipping/availability claims from refactor-owned footer content.
- Preserve unrelated Journal, Newsletter, social, general legal, and studio placeholders unless a direct link conflict exists.
- Delete the unused duplicate `mobile-nav.tsx` if it remains unreferenced; otherwise update it consistently.
- Update root metadata descriptions/keywords only where they make stale storefront or program claims. Do not add structured data or a broad SEO project.
- Update Playwright coverage for desktop/mobile navigation, header actions, footer groups, metadata, and valid hash targets.

## Explicit Non-Goals

- No Journal/Blog/Newsletter redesign.
- No real search, social profiles, Contact route, legal-route buildout, analytics, or structured-data project.
- No new standalone Programs or Products routes unless repository reality changes before implementation.
- No invented topbar promotions or SEO claims.

## Data / Client Requirements

- Navigation concepts: About, Programs, Products, Register, and existing Journal as supported by the one-page architecture.
- Product and program names must come from approved centralized content where displayed.
- Ask the client before retaining any signed-copy, shipping, availability, capacity, or timing promotion.

## Edge Cases

- Every non-placeholder hash link must resolve to exactly one element.
- Mobile menu must still close, unlock body scrolling, and preserve Escape behavior after action removal.
- Removing header actions must not collapse or misalign the menu button at intermediate widths.
- Footer links for products without dedicated anchors should not fabricate per-product URLs.

## Verification

- Search application source and rendered output for `#shop`, `#book`, `Book a call`, `Shop the store`, former program/product names, `Add to cart`, and the cart count.
- Test desktop and mobile links for Programs, Products, Register, and Journal.
- Test mobile menu open/close, body scroll locking, and responsive header alignment.
- Assert updated metadata no longer claims shop drops or unapproved offers.
- Run `npm run lint`, `npm run build`, focused `npm run test:e2e`, and `git diff --check`.

## Completion Criteria

- Site-wide navigation and conversion copy match the final Programs/Products/registration model.
- Fake cart, shop, book-specific navigation, booking, and cohort promotion language is gone.
- Existing responsive navigation behavior remains intact.
- Unrelated out-of-scope placeholders are not expanded into new work.
