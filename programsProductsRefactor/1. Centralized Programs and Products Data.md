# 1. Centralized Programs and Products Data

Status: Complete  
Depends On: None

## Goal

Create the static content foundation for the one approved coaching program and four approved products without changing the visible home page yet.

## Context

- `lib/content/home.ts` currently defines `Program`, `ShopProduct`, `programs`, `bookContent`, `shopCategories`, `shopProducts`, and coaching copy in one large TypeScript file.
- Those records are explicitly marked as mock storefront content.
- `ProgramsSection`, `BookSection`, `ShopSection`, and `CoachingSection` import those exports directly.
- `tsconfig.json` already enables `resolveJsonModule`, and `lib/content/` is the established content location.

## Files / Areas Likely Involved

- Create `lib/content/programs-products.json`.
- Create a small adjacent TypeScript module such as `lib/content/programs-products.ts` for types and exports.
- Inspect `lib/content/home.ts`, but do not remove exports still consumed by the current UI in this task.
- Update `programsProductsRefactor/taskTracker.md` and this file's evidence block.

## Required Changes

- Define JSON records for exactly one program (`Unstoppable You`) and four products (Water Exercise Book, Lunch Bag, Water Bottle, Small Towel).
- Keep JSON content-only. Put TypeScript types, narrowing, helpers, and behavior in the adjacent `.ts` module.
- Give records stable IDs suitable for React keys and form values. Do not use mutable display names as identifiers.
- Model optional/unconfirmed fields explicitly. Product price, description, image, alt text, and `externalUrl` must be nullable/optional instead of fabricated.
- Model the featured book explicitly rather than relying on array position.
- Include only client-confirmed program facts and carefully preserve qualifiers such as `approximately` until display wording is approved.
- Make the TypeScript adapter expose read-only typed program/product collections for later sections.
- Add no runtime fetch, schema package, CMS, or database. A locally maintained JSON file does not warrant a new validation dependency.
- Avoid duplicating presentation-only labels in several components; data may contain CTA intent/status, while JSX owns behavior and layout.

## Explicit Non-Goals

- Do not migrate the current visible sections yet.
- Do not delete mock data while it still has consumers.
- Do not add registration logic, email delivery, product redirects, or navigation changes.
- Do not publish the older private-training pricing as programs or services.
- Do not add client content beyond the supplied facts.

## Data / Client Requirements

- Program: Unstoppable You, 1:1 Coaching, approximately `$2,400`, 8 virtual sessions, approximately 55 minutes, approximately twice weekly.
- Program inclusions may record only the supplied YouTube, workout/homework, nutrition, and measurement/weigh-in facts; public phrasing remains a client-review dependency.
- Products: Water Exercise Book (featured), Lunch Bag, Water Bottle, Small Towel.
- Treat the Lunch Bag `$19.99` as tentative until confirmed. Never include the `$5.95` supplier-cost figure in public content.
- Do not carry current mock book prices forward without explicit confirmation.

## Edge Cases

- Missing product URL: retain `null`; later UI must not create an anchor.
- Missing price/image/description: retain `null` or omit the optional field; do not substitute mock values.
- A later second program should require only another JSON record, not a component rewrite.
- JSON cannot encode imported image objects or functions; use public asset path strings and keep action logic in TypeScript/JSX.
